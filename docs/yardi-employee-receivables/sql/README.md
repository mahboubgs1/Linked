# نصوص SQL — حزمة تقارير مديونية الموظفين

> **حالة هذه النصوص:** مرجعية للتصميم (Reference Implementation). كُتبت لـ SQL Server 2016+
> وتفترض أسماء جداول Yardi قياسية. **لا تُنفَّذ في أي بيئة قبل إكمال بوابة التحقق من السكيما**
> الموصوفة في [`../README.md §4`](../README.md) وتثبيت النتائج في `EMPRCV_SchemaMap`.
> كل موضع يحتمل الاختلاف معلّم في الكود بـ `-- VERIFY:`.

## قواعد ملزمة

1. **لا تعديل على أي كائن Yardi قياسي** — ولا حتى إضافة فهرس.
2. **لا قراءة مباشرة من جداول Yardi** خارج `vw_Src_*`.
3. `vw_Src_UserSecurity` تُسلَّم بحالة **fail-closed** (لا تُرجع صفوفاً). تنفيذها ضد جداول
   أمان Voyager لدى العميل شرط للإطلاق — والتحقق منه مضمّن في `usp_Config_Validate`.
4. `@UserId` يُمرَّر من جلسة Voyager كمعامل مخفي؛ السماح بتعديله يدوياً يُبطل طبقة الأمان.
5. كل النصوص قابلة لإعادة التنفيذ (`CREATE OR ALTER` / `IF NOT EXISTS`).

## اختبار قبول طبقة العزل (إلزامي قبل أي شيء لاحق)

```sql
-- لكيان وحساب وفترة معلومة، يجب أن تطابق النتيجة تقرير ميزان المراجعة القياسي في Voyager
SELECT SUM(Amount)
FROM emprcv.vw_Src_GLTrans
WHERE EntityId = @EntityId AND AccountId = @AccountId AND PostDate <= @AsOfDate;
```

إن لم تطابق: توقّف. المشكلة في خريطة السكيما (اسم عمود المبلغ، اتجاه الإشارة، الدفتر،
أو حالة الترحيل) — وليست في التقارير.
