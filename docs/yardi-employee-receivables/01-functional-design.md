# 01 — وثيقة التصميم الوظيفي (Functional Design Document)

**النظام:** Yardi Voyager · **الوحدة:** General Ledger / Employee Receivables
**الإصدار:** 1.0 (مسوّدة للاعتماد) · **الجهة الطالبة:** قسم المالية

---

## 1. خلفية الطلب والهدف

مديونية الموظفين (سُلف، قروض، عهد، مصاريف سفر، خصومات، غرامات) مسجّلة حالياً في حسابات
الأستاذ العام دون تقرير موحّد يعرضها على مستوى الموظف. النتائج:

- لا توجد رؤية إدارية موحّدة للمديونية عبر الشركات والكيانات.
- تسوية أرصدة الموظفين تتم يدوياً في Excel قبل كل إقفال.
- المدقق الخارجي يطلب مصادقات أرصدة (Balance Confirmations) في نهاية السنة، وتُعدّ يدوياً.

**الهدف:** حزمة تقارير معيارية داخل Voyager تُخرج المديونية على مستوى الموظف حتى تاريخ معيّن،
مع كشف تفصيلي مدقّق، ونموذج اعتماد رصيد جاهز للتوقيع، دون أي معالجة يدوية خارج النظام.

### 1.1 أهداف قابلة للقياس

| # | الهدف | المؤشر |
| - | ----- | ------ |
| G1 | إلغاء الإعداد اليدوي لكشوف المديونية | 0 ساعة Excel شهرياً (حالياً ≈ 12 ساعة) |
| G2 | مطابقة تامة مع ميزان المراجعة | فرق = 0 بين مجموع التقرير ورصيد حسابات المديونية |
| G3 | إصدار مصادقات نهاية السنة | 100% من الموظفين النشطين ذوي الرصيد ≠ 0 خلال يوم عمل واحد |
| G4 | تتبّع المصادقات المستلمة | سجل يعرض نسبة الاستلام لحظياً للمدقق |

### 1.2 خارج النطاق (Out of Scope)

- إنشاء أو ترحيل قيود مديونية (التقارير للقراءة فقط).
- احتساب فوائد أو جداول سداد القروض.
- التكامل مع أنظمة رواتب خارج Yardi (يُعالَج كمرحلة ثانية عبر مصدر موظف إضافي).
- التوقيع الإلكتروني المعتمد (يُصدر النموذج ورقياً/PDF؛ التوقيع الرقمي مرحلة لاحقة).

## 2. الأدوار والمستخدمون (Personas)

| الدور | الاستخدام | مستوى الوصول |
| ----- | --------- | ------------ |
| المدير المالي (CFO) | R1 على مستوى المجموعة | كل الكيانات، قراءة |
| محاسب / مراقب مالي | R1 + R2 + إصدار R3 | كياناته المصرّح بها |
| مدير الموارد البشرية | R2 لموظف محدد + R3 | الكيان + الموظفين التابعين |
| مدير القسم | R1 مفلتر على قسمه | شريحة القسم فقط (Row-Level) |
| المدقق (داخلي/خارجي) | R1 + R2 + سجل المصادقات | قراءة فقط، حساب مؤقت مسجَّل |

## 3. التعريفات المعتمدة (Business Definitions)

| المصطلح | التعريف المعتمد |
| ------- | --------------- |
| **مديونية الموظف** | صافي رصيد مدين للموظف في الحسابات المُعرَّفة ضمن نطاق `EMPRCV_AccountScope` |
| **تاريخ الرصيد (As-of Date)** | تاريخ الترحيل (Post Date)؛ تُدرج كل الحركات ذات `PostDate <= AsOfDate` |
| **الفترة (Period)** | فترة Voyager المحاسبية المرتبطة بتاريخ الترحيل |
| **العمر (Aging)** | عدد الأيام بين تاريخ نشوء المديونية غير المسدّدة وتاريخ الرصيد |
| **الرصيد الافتتاحي** | صافي الحركة قبل `FromDate` (لكشف الحساب) |
| **الفئة (Category)** | تصنيف وظيفي للمديونية (سلفة / قرض / عهدة / سفر / غرامة / أخرى) مشتق من الحساب |
| **الموظف النشط** | حالة الموظف في المصدر = نشط، وتاريخ نهاية الخدمة فارغ أو > تاريخ الرصيد |
| **الرصيد المدين (Dr)** | موجب = الموظف مدين للشركة. الرصيد الدائن (Cr) يظهر بإشارة سالبة |

### 3.1 تمثيل الموظف — المصادر المدعومة

يدعم الحل أربعة مصادر لتعريف الموظف داخل حركة GL، ويمكن تفعيل أكثر من مصدر معاً:

| المصدر | الوصف | متى يُستخدم |
| ------ | ----- | ----------- |
| `VENDOR` | الموظف مُعرَّف كمورد في وحدة الدفعات | الأشيع: صرف السلف عبر AP |
| `SEGMENT` | الموظف شريحة ضمن رقم الحساب المُقسّم | عند وجود شريحة "موظف" في السيجمنتيشن |
| `SUBACCT` | حساب فرعي مستقل لكل موظف | دليل حسابات تفصيلي |
| `REF` | رقم الموظف في حقل مرجع/وصف الحركة وفق نمط محدّد | حل انتقالي، الأدنى موثوقية |

> القاعدة: كل حركة ضمن نطاق الحسابات **يجب** أن تُنسب إلى موظف واحد. الحركات التي تفشل
> عملية النسبة تظهر في مجموعة `#UNMAPPED` ولا تُحذف أبداً — ضابط اكتمال إلزامي (راجع 7.2).

## 4. التقرير الأول — ملخص مديونية الموظفين (`EMPRCV-R1`)

**الغرض:** صف واحد لكل موظف يعرض رصيده حتى تاريخ معيّن موزّعاً على الأعمار والفئات.

### 4.1 الفلاتر (Parameters)

| # | الفلتر | النوع | إلزامي | الافتراضي | ملاحظات |
| - | ------ | ----- | ------ | --------- | ------- |
| P1 | الشركة / الكيان | متعدد الاختيار | نعم | كيانات المستخدم المصرّح بها | يُقيَّد بأمان Voyager |
| P2 | تاريخ الرصيد (As-of) | تاريخ | نعم | آخر يوم في الشهر السابق | أساس كل الحسابات |

### 4.3 قواعد الأعمال

| # | القاعدة |
| - | ------- |
| BR1 | تُدرج الحركات المرحّلة فقط (`Posted`)، ودفتر التقرير = Accrual |
| BR2 | القيود العكسية والقيود المعكوسة تُدرج بقيمتها الفعلية ولا تُحذف (شفافية التدقيق) |
| BR3 | الرصيد الدائن (الشركة مدينة للموظف) يظهر بإشارة سالبة ولا يُقصى من التقرير |
| BR4 | أعمار الرصيد الدائن تظهر في عمود "غير مطبّق (Unapplied Credit)" منفصل |
| BR5 | الموظف منتهي الخدمة ذو رصيد ≠ 0 يُبرز بلون تحذيري (مؤشر مخاطر تحصيل) |
| BR6 | التقرير للقراءة فقط ولا يعدّل أي بيانات |
| BR7 | لا يظهر أي كيان خارج نطاق صلاحية المستخدم، حتى في الإجماليات |

## 5. التقرير الثاني — كشف حساب تفصيلي للموظف (`EMPRCV-R2`)

**الغرض:** حركة تفصيلية مرتّبة زمنياً برصيد متحرك، تُستخدم كمستند تسوية مع الموظف
ودليل تدقيق مؤيّد لرصيد R1.

### 5.1 الفلاتر

| # | الفلتر | النوع | إلزامي | ملاحظات |
| - | ------ | ----- | ------ | ------- |
| P1 | الكيان | متعدد | نعم | قد يمتد الموظف عبر كيانات |
| P2 | الموظف | اختيار مفرد/متعدد | نعم | يُمرَّر تلقائياً عند الدرل داون من R1 |
| P3 | من تاريخ | تاريخ | نعم | يُحتسب ما قبله كرصيد افتتاحي |
| P4 | إلى تاريخ | تاريخ | نعم | يطابق As-of في R1 |
| P5 | فئة / مجموعة حسابات | متعدد | لا | |
| P6 | نوع المستند | متعدد | لا | قيد / فاتورة / دفعة / رواتب |
| P7 | إظهار تفاصيل المستند (Drill-down) | نعم/لا | لا | يوسّع سطور المستند المقابلة |
| P8 | إظهار القيد المقابل (Contra Account) | نعم/لا | لا | مفيد للمدقق |

### 5.2 الحقول

| # | الحقل | ملاحظات |
| - | ----- | ------- |
| C1 | تسلسل | ترقيم متسلسل داخل الكشف |

| C7 | الحساب (رقم + اسم) | |
| C8 | الفئة | |
| C9 | شرائح السيجمنتيشن | أعمدة ديناميكية حسب الإعداد |

| C12 | دائن | مبلغ |

```

  الرصيد الافتتاحي كما في [من تاريخ]                    XX,XXX.XX
─────────────────────────────────────────────────────────

─────────────────────────────────────────────────────────
```

### 5.4 قواعد الأعمال

| # | القاعدة |
| - | ------- |
| BR8 | الرصيد الختامي في R2 **يجب** أن يساوي رصيد الموظف في R1 لنفس التاريخ والنطاق |
| BR9 | ترتيب الحركات ثابت وحتمي (Deterministic) لضمان تطابق الرصيد المتحرك عند إعادة التشغيل |
| BR10 | عند تعدد الكيانات يُطبع كشف منفصل لكل كيان مع صفحة إجمالي موحّد اختيارية |
| BR11 | تظهر ملاحظة صريحة عند وجود حركات بعد `إلى تاريخ` (احتمال تغيّر الرصيد لاحقاً) |

## 6. التقرير الثالث — نموذج اعتماد رصيد الموظف (`EMPRCV-R3`)

**الغرض:** مستند رسمي بصفحة واحدة لكل موظف يعرض رصيده في نهاية السنة المالية مع نص إقرار
وتوقيع، لتلبية إجراء مصادقة الأرصدة لدى المدقق.

### 6.1 الفلاتر

| # | الفلتر | إلزامي | ملاحظات |
| - | ------ | ------ | ------- |
| P1 | الكيان | نعم | |
| P2 | تاريخ نهاية السنة المالية | نعم | افتراضي: نهاية السنة الحالية في Voyager |
| P3 | نطاق الموظفين | نعم | الكل / قسم / قائمة مختارة |
| P4 | حد أدنى للرصيد | لا | افتراضي > 0 (لا تُصدر نماذج لرصيد صفري) |
| P5 | تضمين ملخص الحركة | لا | إرفاق كشف مختصر خلف النموذج |
| P6 | لغة النموذج | لا | عربي / إنجليزي / ثنائي (افتراضي: ثنائي) |
| P7 | الاعتمادات الاختيارية | متعدد | مدير مباشر / موارد بشرية / مدير مالي / مدقق داخلي |
| P8 | وضع الإصدار | لا | مسوّدة (علامة مائية) / نهائي (يُسجَّل في السجل) |

### 6.2 مكوّنات النموذج

1. **ترويسة رسمية:** شعار الشركة، اسم الكيان، عنوان النموذج، رقم مرجع فريد
   (`EMPRCV-C-{Entity}-{FY}-{EmpCode}-{Seq}`)، تاريخ الإصدار، رقم الصفحة.
2. **بيانات الموظف:** الرقم، الاسم، القسم، المسمى، تاريخ التعيين، الحالة.
3. **جدول الرصيد:** الرصيد الافتتاحي، إجمالي المدين، إجمالي الدائن، **الرصيد النهائي**،
   تفصيل حسب الفئة، وملخص الأعمار.
4. **نص الإقرار (Declaration):** راجع `04-prototypes.md` §4 — نسخة عربية وإنجليزية معتمدة.
5. **خانات التوقيع:** الموظف (اسم/توقيع/تاريخ) + الاعتمادات الاختيارية المفعّلة في P7.
6. **خانة الاعتراض:** خيار "غير موافق" مع مساحة لبيان سبب الاعتراض والمبلغ البديل.
7. **تذييل:** المرجع، تاريخ ووقت الإصدار، المستخدم المُصدِر، جملة "صادر آلياً من نظام Yardi
   Voyager"، ورمز QR اختياري يحمل المرجع للتحقق.

### 6.3 قواعد الأعمال

| # | القاعدة |
| - | ------- |
| BR12 | يُبنى الرصيد من **لقطة مجمّدة** (Snapshot) لتاريخ نهاية السنة، لا من استعلام حي |
| BR13 | أي إعادة إصدار بعد قيود لاحقة تُنتج نسخة جديدة برقم تسلسل جديد + تنبيه بالفرق |
| BR14 | كل إصدار نهائي يُسجَّل في `EMPRCV_ConfirmationLog` (من، متى، أي رصيد، أي مرجع) |
| BR15 | الموظف ذو الرصيد الصفري يُستثنى افتراضياً وقابل للتضمين عند طلب المدقق |
| BR16 | صفحة واحدة لكل موظف (فاصل صفحات إجباري) لتسهيل التوزيع |
| BR17 | يمنع تعديل نص الإقرار من داخل التقرير؛ يُدار كنص إعداد معتمد من الإدارة القانونية |

### 6.4 سجل متابعة المصادقات (Control Log)

تقرير مساند (`EMPRCV-R3L`) يعرض: عدد النماذج الصادرة / الموقّعة / المعترض عليها / المعلّقة،
نسبة الاستلام لكل قسم، وقائمة المتأخرين — وهو المستند الذي يسلَّم للمدقق كدليل اكتمال.

## 7. المتطلبات المشتركة

### 7.1 التصدير

| الصيغة | R1 | R2 | R3 | ملاحظات |
| ------ | -- | -- | -- | ------- |
| Excel (XLSX) | ✔ | ✔ | ✔ (بيانات فقط) | صف ترويسة واحد قابل للفرز، بدون خلايا مدمجة، الأرقام كأرقام |
| PDF | ✔ | ✔ | ✔ (الصيغة الرسمية) | ترويسة/تذييل متكرر، ترقيم "صفحة X من Y" |
| CSV | ✔ | ✔ | – | للتحميل إلى أدوات التحليل |

قواعد التصدير: أسماء ملفات معيارية
`EMPRCV-R1_{Entity}_{AsOfDate}_{yyyymmdd-hhmm}.xlsx`، وتضمين سطر معايير التشغيل (كل الفلاتر
المستخدمة) في أعلى كل مخرج — متطلب تدقيق أساسي لإعادة إنتاج النتيجة.

### 7.2 ضوابط الاكتمال والمطابقة (Audit Controls)

| # | الضابط | التنفيذ |
| - | ------ | ------- |
| AC1 | مجموع أرصدة الموظفين = رصيد حسابات النطاق في ميزان المراجعة | سطر مطابقة إلزامي في تذييل R1 |
| AC2 | لا حركات غير منسوبة لموظف | مجموعة `#UNMAPPED` تظهر دائماً حتى لو صفرية |
| AC3 | R2 يطابق R1 لنفس الموظف/التاريخ | مؤشر مطابقة في تذييل R2 |
| AC4 | R3 يعتمد على لقطة مجمّدة قابلة لإعادة الإنتاج | جدول Snapshot + سجل الإصدار |
| AC5 | أثر تشغيل كامل | `EMPRCV_RunLog`: المستخدم، الوقت، الفلاتر، عدد الصفوف، زمن التنفيذ |

### 7.3 متطلبات غير وظيفية

| # | المتطلب | الهدف |
| - | ------- | ----- |
| NF1 | زمن استجابة R1 | ≤ 10 ثوانٍ لـ 5,000 موظف × 3 سنوات |
| NF2 | زمن استجابة R2 | ≤ 5 ثوانٍ لموظف واحد × 5 سنوات |
| NF3 | إصدار R3 دفعة واحدة | ≤ 5 دقائق لـ 1,000 نموذج PDF |
| NF4 | دعم اللغتين | واجهة ومخرجات عربية (RTL) وإنجليزية |
| NF5 | التوافق مع الترقية | صفر تعديلات على كائنات Yardi القياسية |
| NF6 | الاحتفاظ بالسجلات | سجلات التشغيل والمصادقات ≥ 7 سنوات |

## 9. معايير القبول (Acceptance Criteria)

| # | المعيار | طريقة الإثبات |
| - | ------- | ------------- |
| AT1 | مجموع R1 = رصيد ميزان المراجعة لحسابات النطاق (فرق = 0) | تشغيل مقارن لثلاثة تواريخ |
| AT2 | الرصيد الختامي في R2 = رصيد الموظف في R1 | عيّنة 20 موظفاً |
| AT3 | مجموع أعمار R1 = الرصيد الإجمالي للموظف | فحص حسابي لكل صف |
| AT4 | الدرل داون يفتح المستند الصحيح في Voyager | 10 مستندات من أنواع مختلفة |
| AT5 | التقرير لا يعرض كيانات خارج صلاحية المستخدم | اختبار بثلاثة أدوار مختلفة |
| AT6 | تصدير Excel قابل للفرز مباشرة والأرقام رقمية | فحص يدوي |
| AT7 | R3 صفحة واحدة لكل موظف مع كل خانات التوقيع المطلوبة | عيّنة 50 نموذجاً |
| AT8 | إعادة تشغيل R3 لنفس التاريخ تعطي نفس الأرصدة | مقارنة قبل/بعد قيد بأثر رجعي |
| AT9 | تحقق أهداف الأداء NF1–NF3 على بيانات الإنتاج | قياس موثّق في UAT |
| AT10 | لا حركات في `#UNMAPPED` عند الإطلاق | تقرير الاستثناءات فارغ |

## 10. المخاطر

| RK6 | قيود بأثر رجعي بعد إصدار المصادقات | خلاف مع المدقق | اللقطة المجمّدة + تنبيه الفرق عند إعادة الإصدار |
