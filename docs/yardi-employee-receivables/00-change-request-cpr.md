# 00 — طلب برمجة مخصصة (CPR)

> **Custom Programming Request — Yardi Voyager**
> حزمة تقارير مديونية الموظفين (`EMPRCV`)
>
> هذا هو المستند الأول في الحزمة: البوابة الرسمية التي تُعتمد قبل بدء أي تنفيذ.
> وثائق التصميم `01` إلى `05` ونصوص `sql/` هي **مرفقات فنية** لهذا الطلب.

## 2. الملخص التنفيذي (Executive Summary)

يطلب قسم المالية تطوير ثلاثة تقارير مترابطة داخل Yardi Voyager لمتابعة مديونية الموظفين
(سُلف، قروض، عهد، مصاريف سفر، خصومات) وتلبية إجراء مصادقة الأرصدة الذي يطلبه المدقق الخارجي:

| الرمز | التقرير | الغرض |
| ----- | ------- | ----- |
| `EMPRCV-R1` | ملخص مديونية الموظفين | رصيد كل موظف حتى تاريخ معيّن موزّعاً على الأعمار والفئات |
| `EMPRCV-R2` | كشف حساب تفصيلي للموظف | حركة تفصيلية برصيد متحرك ودرل داون إلى المستند |
| `EMPRCV-R3` | نموذج اعتماد رصيد الموظف | مستند رسمي بإقرار وتوقيع لنهاية السنة المالية |
| `EMPRCV-R3L` | سجل متابعة المصادقات (مساند) | دليل الاكتمال المسلَّم للمدقق |

التقارير تدعم السيجمنتيشن وتعدد الشركات والكيانات، وتُبنى على معاملات الحسابات العامة
بأرصدة حتى تاريخ معيّن، مع تصدير Excel و PDF وتفاصيل درل داون.

**الحل للقراءة فقط ولا يعدّل أي بيانات في Yardi**، ولا يتضمن أي تعديل على كائن قياسي.

## 3. مبرر العمل (Business Justification)

### 3.1 الوضع الحالي

- لا يوجد تقرير موحّد يعرض مديونية الموظفين على مستوى الموظف داخل النظام.
- تُعدّ الكشوف يدوياً في Excel قبل كل إقفال (≈ **١٢ ساعة عمل شهرياً**).
- مصادقات نهاية السنة تُكتب يدوياً لكل موظف، دون سجل موحّد للمُصدَر والمستلم.
- لا توجد رؤية إدارية للمديونية عبر الشركات والكيانات في مستند واحد.

### 3.2 الأثر والمخاطر عند عدم التنفيذ

| # | المخاطرة | الأثر |
| - | -------- | ----- |
| J1 | ملاحظة تدقيق على ضعف ضوابط مصادقة الأرصدة | ملاحظة في تقرير المدقق |
| J2 | خطأ بشري في كشوف Excel اليدوية | أرصدة غير مطابقة لميزان المراجعة |
| J3 | عدم متابعة أرصدة الموظفين منتهي الخدمة | مخاطر تحصيل / خسائر فعلية |
| J4 | استهلاك وقت الفريق المالي في أعمال يدوية متكررة | تأخير الإقفال الشهري |
| J5 | غياب أثر تدقيق لمن اطّلع على البيانات ومتى | ضعف في ضوابط حماية البيانات |

### 3.3 العائد المتوقع

| # | الهدف | المؤشر |
| - | ----- | ------ |
| G1 | إلغاء الإعداد اليدوي | من ≈ ١٢ ساعة شهرياً إلى صفر |
| G2 | مطابقة تامة مع ميزان المراجعة | فرق = 0.00 في كل تشغيل (ضابط آلي) |
| G3 | إصدار المصادقات السنوية | 100% خلال يوم عمل واحد بدل أسابيع |
| G4 | تتبّع نسبة استلام المصادقات | سجل لحظي يُسلَّم للمدقق |
| G5 | ضبط مخاطر التحصيل | قائمة آلية بمنتهي الخدمة ذوي رصيد ≠ 0 |

## 4. النطاق (Scope)

### 4.1 داخل النطاق

1. تقرير `EMPRCV-R1` بكامل حقوله (٢٢ حقلاً) وفلاتره (١٢ فلتراً).
2. تقرير `EMPRCV-R2` برصيد متحرك ودرل داون على مستويين.
3. نموذج `EMPRCV-R3` مع نص الإقرار وخانات التوقيع والاعتمادات الاختيارية.
4. سجل `EMPRCV-R3L` لمتابعة المصادقات.
5. طبقة بيانات مشتركة + جداول إعداد تجعل الحل قابلاً للتوسع بلا برمجة.
6. ضوابط مطابقة آلية (RC1–RC6) وسجل تشغيل للتدقيق.
7. تصدير Excel و PDF و CSV، ودعم العربية (RTL) والإنجليزية.
8. تسجيل التقارير في قائمة Voyager وربطها بمجموعات الصلاحيات.

> التفاصيل الكاملة: المرفق `01-functional-design.md`.

### 4.2 خارج النطاق

| # | البند | السبب |
| - | ----- | ----- |
| O1 | إنشاء أو ترحيل قيود المديونية | الحل للقراءة فقط |
| O2 | احتساب فوائد أو جداول سداد | يُدرس كمرحلة لاحقة (E5) |
| O3 | التكامل مع أنظمة رواتب خارج Yardi | مرحلة ثانية عبر مصدر موظف إضافي |
| O4 | التوقيع الإلكتروني المعتمد | مرحلة لاحقة (E4) |
| O5 | تنقية البيانات التاريخية | مسؤولية العميل — بند مسبق (§6) |
| O6 | مخصص الديون المشكوك في تحصيلها | توسعة مستقبلية (E6) |

## 8. تقدير الجهد والجدول الزمني

| المرحلة | الوصف | أيام عمل (المنفّذ) | أيام عمل (العميل) |
| ------- | ----- | ------------------ | ----------------- |
| M0 | التحقق من السكيما — **بوابة إلزامية** | 4 | 3 (DBA) |
| M1 | جداول الإعداد واعتماد نطاق الحسابات | 3 | 2 (المالية) |
| M2 | طبقة العزل + نواة البيانات + اختبار المطابقة | 5 | 1 |
| M3 | تقرير R1 (الحقول، الفلاتر، الأعمار، التصدير) | 5 | 1 |
| M4 | تقرير R2 (الرصيد المتحرك، الدرل داون) | 4 | 1 |
| M5 | نموذج R3 + سجل R3L + اللقطة المجمّدة | 5 | 2 (المالية + القانونية) |
| M6 | الأداء: جدول التجميع + الوظيفة الليلية + القياس | 3 | 1 |
| M7 | الصلاحيات والاختبار بثلاثة أدوار | 2 | 1 |
| M8 | اختبار القبول (UAT) | 3 | 5 (المالية + التدقيق) |
| M9 | التدريب والوثائق | 2 | 2 |
| M10 | النشر والدعم المكثّف (أسبوعان، جزئي) | 4 | 2 |
| **الإجمالي** | | **≈ 40 يوم عمل** | **≈ 21 يوم عمل** |

**المدة الزمنية:** ٧–٨ أسابيع من تاريخ اعتماد الطلب واكتمال المتطلبات المسبقة.

**أساس التقدير:** التصميم التفصيلي المرفق (`01`–`05`) ونصوص SQL المرجعية الجاهزة في `sql/`،
وهي تختصر مرحلة التحليل والبناء الأولي. التقدير **أولي** ويُعاد تثبيته بعد نتيجة M0، لأن
اختلاف السكيما أو تعدد طرق تسجيل المديونية تاريخياً قد يضيف ٣–٧ أيام على M0/M2.

## 9. البدائل المدروسة (Alternatives Considered)

| # | البديل | التقييم | القرار |
| - | ------ | ------- | ------ |
| A1 | الاستمرار بالوضع الحالي (Excel يدوي) | لا تكلفة تطوير، لكن يُبقي كل مخاطر §3.2 ولا يحل ملاحظة التدقيق | مرفوض |
| A2 | استخدام تقارير Voyager القياسية فقط | لا تعرض المديونية على مستوى الموظف ولا تنتج نموذج مصادقة | غير كافٍ |
| A3 | أداة تحليل خارجية (BI) تقرأ من قاعدة Voyager | تُنتج تحليلاً لا مستنداً رسمياً؛ تُخرج البيانات الحساسة خارج النظام وتُضعف الصلاحيات؛ تحتاج ترخيصاً وبنية إضافية | مرفوض |
| A4 | **حزمة تقارير مخصّصة داخل Voyager (هذا الطلب)** | تبقى البيانات والصلاحيات داخل النظام، ومخرجات رسمية قابلة للتوقيع، وتوافق مع الترقيات | **موصى به** |
| A5 | تطوير على مراحل: R1 أولاً ثم R2/R3 | يقلّل الدفعة الأولى، لكن R3 هو المحرّك الزمني (التدقيق) وR1 وحده لا يحل ملاحظة التدقيق | يُدرس فقط عند ضغط الموازنة |

## 10. تقييم الأثر (Impact Assessment)

| البعد | التقييم |
| ----- | ------- |
| أثر على البيانات | **لا يوجد** — قراءة فقط؛ الكتابة محصورة في جداول مخصّصة (سجلات ولقطات) |
| أثر على العمليات القائمة | لا يوجد — لا تعديل على شاشات أو تقارير قياسية |
| أثر على الأداء التشغيلي | منخفض ومُدار: جدول تجميع ليلي + تشغيل الدفعات خارج الذروة + حد أقصى للصفوف |
| أثر على الترقيات | لا يوجد — لا تعديل على كائنات قياسية؛ يلزم إعادة اختبار طبقة العزل بعد كل ترقية |
| أثر على المستخدمين | إيجابي: إلغاء عمل يدوي؛ يحتاج جلسة تدريب واحدة |
| أثر أمني | يتطلب ضبط صلاحيات مشددة (بيانات حساسة) — مغطّى بست طبقات في `05` |
| أسوأ سيناريو للفشل | تعطّل التقارير فقط — لا فقدان أو إفساد بيانات |
| زمن التراجع | ≤ ١٥ دقيقة لتقرير أو إجراء · ≤ ساعة لإلغاء كامل |
